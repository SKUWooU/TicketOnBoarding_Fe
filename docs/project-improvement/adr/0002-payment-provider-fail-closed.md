# ADR-0002: 실제 결제 제공자 기본 비활성화

- 상태: Accepted
- 결정일: 2026-09-03
- 관련 Issue: Frontend #12

## 맥락

레거시 결제 화면은 렌더링과 동시에 외부 PortOne 스크립트를 로드하고 PG 요청을 실행했다. 현재 프로젝트의 검증 목적은 가상 좌석의 동시성·상태 정합성과 FE/BE 계약이며, 실제 금융 거래나 운영 결제 연동이 아니다. 로컬 테스트 중 실수로 외부 결제를 호출하면 비용·데이터·테스트 재현성 문제가 생긴다.

## 결정

- PG 호출은 `paymentProvider` 모듈 뒤로 격리한다.
- 기본 구현은 외부 스크립트를 로드하지 않고 `PaymentProviderUnavailableError`로 종료한다.
- 실제 PG 키가 환경변수에 존재하더라도 자동 활성화하지 않는다.
- 단위·통합 테스트는 모듈을 명시적인 fixture로 대체한다.
- 실제 PG 도입은 승인·취소·환불·webhook 검증·secret 관리·운영 profile 차단 조건을 별도 Issue에서 합의한 뒤 진행한다.

## 결과

결제 페이지 진입만으로 외부 I/O가 발생하지 않는다. Checkout과 검증 예약의 Frontend 흐름은 재현 가능한 fixture로 검증할 수 있다. 반면 현재 브라우저에서는 실제 결제 성공을 만들 수 없으며, 이것은 의도한 안전 제한이다.

## 재검토 조건

- 실제 PG sandbox 계정과 callback/webhook 계약이 준비된다.
- Backend가 결제 승인 금액·주문 번호·상태를 독립적으로 검증한다.
- 로컬·CI·운영 profile의 어댑터 활성화 조건과 secret 관리가 분리된다.
- 승인·실패·취소·환불·timeout·중복 callback E2E 시나리오가 정의된다.
